# PRN Order Viewer — 처방 확인 교육용 운영 범위

> 2026-10-10 결정 · 기준 v0.5.2 · 합성 데이터 전용, 실제 투약 금지

## 확정된 교육 목적
PRN을 실제 병원에서 없던 새 조회 기능으로 소개하지 않는다. 이미 유사한 조회/선택 기능이 존재한다는 현장 의견이 있으며 실제 nU의 기능 범위는 직접 검증하지 않았다.

**현재 앱을 '가상 의사 처방을 읽고, PRN 조건·용량·경로·간격·상태·변경 이력·간호사 열람 확인 기록을 구별하는 처방 확인 교육/시연 도구'로 활용한다.** 실제 투약 적격성, 의사의 처방 적정성, 간호사 독립 판단, 임상 오류 감소 효과를 검증한 것으로 취급하지 않는다.

## 권장 교육 시나리오
| 순서 | 앱에서 하는 일 | 교육 중 확인할 핵심 질문 |
|---|---|---|
| 1 | 가상 환자 선택, 전체 약물/PRN 분류 전환, 검색 | 현재 선택한 환자의 처방이 맞는가? 정규·PRN·STAT이 구별되는가? |
| 2 | PRN 상세의 '현재 처방 핵심 확인' 확인 | 적응증·조건·1회 용량·경로·빈도·최대 지시 중 무엇이 **명시**됐고 무엇이 **미기재**인가? |
| 3 | 모의 의사 처방 변경(보류·재개·중지·지시 수정) 후 재조회 | 현재 유효한 버전이 무엇이며 최초 입력 원문과 무엇이 다른가? |
| 4 | 간호사 모의 열람 확인 및 이력 조회 | '처방 작성', '간호사가 읽었다는 확인', '투약 수행', '간호기록'은 왜 서로 다른가? |

## 교육상 특히 주의할 사항
- 시드 가상 처방 18건 중 독립된 `administration_condition` 필드는 저장되어 있지 않다. 상세에서는 **미기재**로 보고, 다른 문장이나 약물명으로 임상 조건을 추정하지 않는다.
- 현재 처방의 `active`는 **투약 가능한 상태라는 보증이 아니다**. 약물·환자·상태 안전성 판단을 이 앱에서 하지 않는다.
- 변경 이전 구조화 지시가 `stale`로 표시되는 경우 현재 지시로 사용하지 않는다.
- 새 PRN에 명시적 투여 조건을 입력해 보는 것은 **합성 입력 검증**이지 현실 병원 지침을 만들어내는 활동이 아니다.
- 간호사 '열람 확인'은 모의 이벤트이며 처방 승인·전자서명·투약·평가·간호기록이 아니다.
- 실제 환자/직원정보, 병원 내부 원문·코드, 진료지침을 승인 없이 수집·업로드·저장하지 않는다.

## 실행 및 평가
1. 비공개 저장소의 코드를 로컬에서 열고 간단한 HTTP 서버로 실행한다. 예: 프로젝트 루트에서 `python -m http.server 8000` → `http://127.0.0.1:8000`.
2. 교육 시작 전에 **교육용·임상 미검증** 표시와 합성 환자 데이터 여부를 확인한다.
3. 위 1–4단계에서 학습자가 화면상의 *명시 사실/누락/과거 버전/업무 이벤트*를 정확히 구별하는지 관찰한다.
4. 코드 검증은 `node --test tests/*.test.cjs` 및 기존 CI로 확인하되, 시험 통과가 학습 효과·임상 유용성·병원 내 도입 검증을 의미하지 않는다고 설명한다.

## 개발 동결과 후속 프로젝트
- v0.5.2를 교육용 기술 안정 버전으로 보존한다. 신규 PRN 임상 기능·자동 계산·실제 투약 기록·서버 저장·EMR 연동은 진행하지 않는다.
- 다음 우선 작업은 **간호처방 UI/UX 개선 프로젝트에서 실제 업무상 문제를 확인하는 사용성 평가 준비**다.
- 다른 프로젝트와 저장소·환자/직원 ID·DB를 자동 병합하지 않는다. 장기 통합 방향은 별도 검증 및 사용자 결정에 따름.

**이번 결정으로 기존 PRN 구현·사용자 데이터·UI·저장 정책은 수정하지 않았다.**
