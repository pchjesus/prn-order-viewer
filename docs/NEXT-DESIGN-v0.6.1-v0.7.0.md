>
> **상태: PROPOSAL / NOT IMPLEMENTED.** 이 문서의 기능·정책은 아직 승인되거나 구현·검증된 것이 아니다. 기존 작동·데이터·임상적 한계는 현재 v0.6.0 기준이다.

## 1. 설계 의도
- 앱의 목적은 **가상 PRN 약물처방 확인 교육**. 실제 병원에 없던 PRN 조회 기능 개발 또는 투약 적격성 판단 도구가 아님.
- v0.6.0 B안에서 만든 구조화 환자정보, 독립 가상의사/주치의, 접이식 Kardex, Excel 근무표 보관함을 보존하되, **잘못된 데이터 해석을 먼저 줄인다**.
- v0.6.1에서는 안정성·가독성·검증을 개선하고, v0.7.0에서는 근거가 있는 합성 처방만으로 학습 순서를 구성한다. 의료정보 확장/임상 규칙 자동판단/대규모 EMR 통합은 하지 않는다.
- 우선순위 근거: 코드 정적 감사 + [v0.6.0 실제 CI 성공](https://github.com/pchjesus/prn-order-viewer/actions/runs/38335597285). **현직 간호사 사용성/기관 적용 결과는 아직 없다.**

## 2. 현재 확인된 구현과 미검증 구분
| 대상 | 코드·기록으로 확인 | 제한 및 잠재 위험 |
|---|---|---|
| 근무표 Excel | `roster-import-parser.js`가 날짜행/이름열 자동탐색; `roster-library-ui.js`는 선택 날짜·듀티 일부만 미리보기 | 같은 파일의 다른 날짜·예외값을 한눈에 확인하기 어려움; 특정 서식 외 데이터는 불확실 |
| 선임 그룹 | `roster-import-config.js`에 **Charge 8명/중간년차 6명/나머지 저연차** 가정이 들어 있음 | 합성 근무표에 실제 검증되지 않은 경력·직책을 부여할 위험; **교육용 PRN에는 선임 배치 규칙 불필요** |
| 누락 날짜 | `validateMonth`가 없는 날짜를 **경고**로 반환하지만 저장은 가능 | 사용자에게 완전한 월간 근무표로 보일 수 있음 |
| 근무표 보관함 | `prnRosterTeachingDB_v1`, 월별 ID, `revision` 확인, 저장≠사용, 활성 삭제 시 해제 | 자동검사는 주로 단일 월·단일 탭의 생성/사용/삭제/복원을 확인. 여러 월·덮어쓰기·충돌·저장 실패/용량 부족 미검증 |
| 활성화 | 근무표 1개를 수동 선택하여 활성화, 조회 날짜는 별도 입력 | 활성 월과 조회 월이 다르면 '자료 없음'과 혼동될 가능성 |
| Kardex | `order-sheet-ui.js`가 PRN·정규·STAT을 `details`로 분리, 개별 주문 보존 | 매 렌더링 `replaceChildren`으로 펼침 상태를 재생성; 상세에서 어떤 정보가 가장 중요한지 실제 사용자 평가 없음 |
| 환자정보 | `data/patient_profiles.json` + `data/patients.json` + `data/teaching_case_context.json` | 같은 인계·현재 상태 의미가 복수 파일에 존재하므로 중복/갱신 불일치 위험 |
| 시나리오 자료 | 가상 환자 4명, 기본 처방 18건, 후보 약물 107개. 누락 지시를 추정하지 않음 | 추가 검사·알레르기·진단·투약 조건을 근거 없이 채울 수 없음 |
| 검증 | Node 81/81, 기존/신규 Chromium 통과 | 모든 엑셀/브라우저/다중 탭/임상 사용성을 검증한 것은 아님 |

위 위험은 **코드에서 발견한 구조적 가능성**이며, 실제 임상 오류나 사용자 불만이 재현됐다는 주장이 아니다.

## 3. 제안 릴리스 A — v0.6.1 (우선 / 안정화 패치)

### A1. 근무표 의미 안전성 [P0]
- **핵심 권고:** PRN 근무표의 사용자 UI에서는 `Charge/중간년차/저연차` 등 **원본이 검증하지 않은 직책·경력 분류를 표시하지 않는다**. 실제 근무코드 D/E/N/NC와 가상의 명단만 보여준다.
- MICU 전용 파서의 그룹 분류는 과거 기록·앱 상호 호환 목적으로 보존하되, PRN 교육 화면에서는 "그룹 미확인" 또는 직책 비표시. **기존 IndexedDB의 저장값을 자동 마이그레이션/수정하지 않는다**.
- 기존 MICU JSON 백업 조회는 현재 표시·데이터 교환 동작을 유지한다. 새 Excel과 옛 JSON의 표시 정책을 혼동하지 않도록 서로 구획한다.
- 장기 대안(명시적 동의 필요): PRN용 중립 Excel 파서 프로필과 `sourceRole` 검증 규칙을 별도로 만들되 MICU 저장소·원본 로직은 수정하지 않는다.

### A2. Excel 전체 미리보기/결함 확인 [P0~P1]
- 제안 화면: **업로드 → 시트·연월·열·행 검증 → 월 전체 요약(읽힌 인원·날짜·누락 날짜·경고 수) → 선택 날짜별 D/E/N·비근무 내역 확인 → [저장] → 보관함 [사용]**.
- 예외를 한 영역에 배치: 잘못된 날짜/중복 날짜/알 수 없는 근무코드/이름 열 누락/동명이인/비정상 행/빈칸.
- 허용 규칙 구분: **구조 오류/알 수 없는 근무코드 = 저장 차단**; **일부 날짜 누락/동명이인/빈칸 = 경고 + 명시 재확인** (권고안, 확정 전 사용자 결정).
- 실제 인원 데이터가 아닌 **합성 Excel**로만 테스트한다. 파일명과 체크박스는 비식별화/사용 승인 자체를 증명하지 않는다.

### A3. 보관함 및 UI 경계 [P1]
- 저장된 여러 월과 사용 중인 월을 분리 표시; 조회 날짜가 활성 월과 다르면 **"월 불일치 · 자동 전환 없음"** 안내.
- 덮어쓰기/삭제 전 파일명·연월·현재 사용 상태·revision 확인, 취소 시 현상 유지.
- 기본 수동 활성화 정책 유지, 모의 로그인과 간호사 열람 확인 자동 연동 금지.
- 기존 Excel 보관함과 MICU JSON 임시 조회를 화면에서 시각적으로 분리(서로 다른 저장/삭제/조회 정책 설명).
- 가능하면 파일 오류 후 이전의 분석 후보가 다시 저장되지 않도록 무효화 상태와 파일 선택 변경 시 UI 리셋을 검증한다.

### A4. Kardex/UI 회귀 개선 [P1]
- 기본 화면은 환자·주치의·알레르기 **확인 상태**, PRN·정규·STAT 건수와 유효/보류/중지 상태로 간단히 요약.
- 개별 약물의 **최신 명시 지시**와 **최초 원문·변경 이력**을 시각적으로 구분. 유효 상태가 투약 가능 판정이 아님을 유지.
- 접이식 펼침 상태: 현재처럼 환자 변경 때 초기화하되 같은 환자/단순 새로고침(화면 렌더) 시 같은 order ID의 펼침 상태를 유지하는 방안 권고. 새로고침 후 주문 원본 상태는 기존 정책대로 탭 메모리 소실.
- 모바일 너비 390px, 키보드 Tab/Enter/Space/summary semantics, 스크린리더 텍스트 대비 검증. 실제 사용자 가독성은 별도 수동 점검.

## 4. 제안 릴리스 B — v0.7.0 (PRN 처방 확인 교육 중심)

### B1. 교육 과제 수준별 구분
- **기본(가상 환자 P001)**: 환자 일치, 정규/PRN 구분, 적응증·PRN 투여 조건/용량/경로/간격 중 *명시 vs 미기재* 확인, 주치의 vs 작성자 구별.
- **심화(가상 환자 P003)**: 동일 약물의 유효·중지 처방, 보류 상태, 처방 변경 전/후 버전, 같은 근무조의 열람 확인과 투약 수행의 구분.
- **반례(P002)**: PRN 0건 환자에서 **정상적인 '조회 결과 없음'**을 오처방 누락 또는 투약 필요성 판단으로 오해하지 않는가.
- **추가(P004)**: 경구·외용·점안 제형/경로 구분. 특정 약물 선택 정답·투약 적정성 자동판정은 포함하지 않음.

### B2. 정보 모델/교육 답안
- 새로운 교육 과제는 `scenario_id`, `patient_id`, `target_order_ids`, `learning_objective`, `visible_facts`, `unknown_facts`, `question`, `scoring_rule_type` 정도만 **별도 읽기 전용 합성 파일**로 제안.
- `scoring_rule_type`은 **텍스트·상태·버전 식별** 등 명시적 데이터 확인만 허용. 임상 판단/용량계산/투약 허가 여부에 대한 점수화·추천을 금지.
- 이미 존재하는 `patient_profiles.json`/ `teaching_case_context.json`에 같은 병력 문장을 중복 추가하지 않는다. 참조 ID 기반으로 연결.
- `allergy.status=unknown` 등의 **미확인 상태를 '없음'으로 변경하지 않음**. 활력징후·검사 값·장치 유무는 공식적 교육 필요성과 데이터 근거를 검토하고 사용자 승인 후에만 추가.

### B3. 교육 UI 대안 및 평가
| 대안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| B-1: 기존 앱 안내 카드 | 기존 PRN·Kardex 옆에 단계별 질문을 접이식으로 표시 | 기존 UI/처방 변경 없이 작게 구현; 권고 | 학습 흐름이 단순할 수 있음 |
| B-2: 별도 교육 모드 | 가상 학생 진행도/답안 확인/피드백을 새로운 화면에서 진행 | 집중된 학습 동선 | 상태관리·기록 및 UX 복잡도 증가 |
| B-3: 자동 처방/임상판단 시뮬레이터 | 증상·환자수치 기준 자동 투약 타이밍·허가 판단 | 교육 가능성은 있으나 임상 검증 비용 높음 | **현 단계 부적절, 진행하지 않음** |

**권고:** B-1을 먼저 소규모 프로토타입으로 만든 후, 실제 학습자의 탐색·오해 사례가 확인될 때 B-2 검토. 교육 점수/진행도 저장 기능은 현재 도입하지 않는다.

## 6. 단계별 구현 및 테스트 계획
1. **Gate 0 — 사용자 승인/명세 고정:** D1–D6 중 중요한 UI·데이터 정책만 결정. 사용자 확인 전 v0.6.1 구현 착수하지 않는다.
2. **Patch 1 — 파서 표시·미리보기 개선:** 경고·날짜 누락/직책 오해 방지. 테스트: 정상/중복/미완성/미지정/악성 서식, 28·29·30·31일, NC 규칙.
3. **Patch 2 — 보관함 안정성:** 두 개 이상 월, 사용 후 월 이동/복귀, 같은 월 덮어쓰기 승인/취소, 사용 중 삭제, 다중 탭 교체 충돌, IndexedDB 접근 불능·quota 실패. **기존 근무표 저장 내용 자동 변환 금지**.
4. **Patch 3 — Kardex 요약/접이식:** 환자 변경·처방 변경·이력 변경 때 ID/상태와 펼침 컨텍스트 유지 확인, 키보드 및 모바일 회귀. 기존 원본/변경 이력 표시 보호.
5. **v0.6.1 Release Gate:** 기존 Node 81건 + 신규 실패/경계 테스트, 기존 `tests/browser_smoke.py` 및 `tests/v0.6.0-browser.py` 포함 실 HTTP Chromium 자동검사. 실제 실행한 결과만 성공으로 기록. 사용자 직접 화면 검수 별도.
6. **v0.7.0 이후:** 합성 환자별 교육 질문(읽기 전용)과 학습자 이해도 평가. 화면을 변경하기 전 동일 환자/처방 결과의 교육 목표와 오해 예방 기준 확정.

## 7. 우선 검토할 근거와 보류 범위
- **확정 사실:** v0.6.0 CI 성공, 코드상의 MICU 선임 그룹 가정, 날짜 경고/저장 허용, 선택 날짜 중심 미리보기, 단일 활성 월, 메모리·IndexedDB 영역 분리.

- **사용자 승인 필요:** 누락 날짜·중복 이름 처리, 직책 노출, 펼침 기본 정책, 신규 교육 모드/데이터 보존 등.
