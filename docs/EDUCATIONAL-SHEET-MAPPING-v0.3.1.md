# v0.3.1 — 교내 실습자료 기반 사례·Kardex·처방지 구조

작성일: 2026-10-10

## 자료의 성격 및 사용 범위

### 사용자 제공 1: `icn 워크리스트.pdf` (12쪽)
- 1쪽: 활력징후·욕창/낙상 예방 간호의 환자 상황과 처방 리스트.
- 2–4쪽: SC와 BST, 관련 임상 상황 및 처방 리스트·슬라이딩 스케일 형식.
- 5–7쪽: ID/IM/IV 술기별 간단한 환자 상황과 처방지.
- 8쪽: 통증·배액관과 처방 리스트.
- 9–12쪽: 산소화·수혈·유치도뇨 관련 환자 상황과 처방지.
- **활용:** 시나리오 요약 / 간호 관찰·수행 과제 / 처방과 간호술기의 연결에 대한 **구성 방식**.

### 사용자 제공 2: `2026사례기반 실무실습 사례자료.pdf` (17쪽)
- 4·7·10·13쪽: 실습 주제 → 사례 개요 → Kardex → 평가 항목의 구성.
- 5·8·11·14쪽: 'Order Manage' 형식 처방지(정규/추가 묶음, 작성시간, 처방자, 전달사항 및 약물·검사·처치 관련 정보).
- 16–17쪽: 술기별 지식·피드백·성찰 평가 구조.
- **활용:** 가상 인계·처방지의 구획 및 표 열 설계.
- 특히 검사·혈액제제·처치·전달 지시가 섞이는 사례가 존재하므로, 이를 전부 약물처방으로 분류하면 안 됨.

## 가상 환자 시나리오

기존 환자 4명은 변경하지 않으며, `data/teaching_case_context.json`에 동일 가상 환자 ID를 가진 **독립 보조 교육 시나리오** 4건을 추가한다.

- `DEMO-P001`: 복부 수술 후 회복(통증·오심·일반 관찰)
- `DEMO-P002`: 검사 후 회복/기본 사정(PRN 0건 확인)
- `DEMO-P003`: 기도질환 악화(산소화 관찰 및 PRN 구별)
- `DEMO-P004`: 피부·안구 알레르기 증상(제형·경로 구분)

필드: `patient_id`, `scenario_title`, `skill_topics`, `kardex_notes`, `watch_points`, `worksheet_reference`.
원본 PDF의 인명·등록번호·원본 처방코드·환자별 용량값은 추출/전사하지 않음. 원본 사례와 동일한 환자/처방을 재현한다고 주장하지 않음.

## 구현 결과

- `order-sheet-model.js`: 시나리오 연결 검증, 환자별·작성시각·작성자·기존/추가 묶음, PRN/STAT 구분, 원본 데이터 비변경.
- `order-sheet-ui.js`: 접이식 사례·Kardex 및 'Order Manage' 형식 테이블(긴 표 가로 스크롤, DOM `textContent`만 사용).
- `index.html`/`styles.css`: 기존 전체약물/PRN/가상의사 입력/MICU 조회 UI를 유지하고 선택적 패널 추가.
- `doctor-ui.js`: **환자 변경 시 미등록 처방 입력값 초기화**(환자 혼입 방지).
- `data/teaching_case_context.json`: 4개 가상 학습용 인계 자료.
- `tests/order-sheet-model.test.cjs`: 7개 신규 테스트.

## 검증 및 남은 과제

- 기존 핵심 14개 + 의사 입력 8개 + 새로운 사례/처방지 7개 = **29/29 테스트 통과**. 현재 GitHub 원격 파일을 참조한 별도 JS 실행 환경에서 Node 테스트 함수를 평가함.
- MICU 백업 연동 테스트 파일과 실제 브라우저 UI 렌더링은 이번 실행에서 전체 자동 재검증하지 않음.
- 사용자 PC/Codespaces의 8000 포트 웹서버에서 시각 검수는 **MVP 완성 시점에 진행**(사용자 의사 반영).
- 원본 약물 107개·환자 4명·가상 처방 18건·처방열람 확인 데이터 및 MICU 저장소에는 수정 없음.
- 과제의 약물 용량·경로 등 의료정보는 실제 처방 검증이 아니며 임상 적용 금지.
- 현재는 약물 처방지 **미리보기만** 구현. 비약물 검사·드레싱 처방의 실제 입력과 D/C·변경, 의사 서명, 기록 영속화는 **구현하지 않음**.

## 후속 설계

1. 정규/추가/변경/중지(D/C) 이벤트와 **의사 작성·간호사 열람 확인**을 서로 다른 이력으로 모델링.
2. 비약물 `ServiceRequest` 등 검사·처치 영역 확장: 검사명과 검체 종류·채취 용기(SST/EDTA 등)를 구분.
3. 처방 지시의 '1일 용량·1회 수량'은 약품/단위에 대한 검증된 구조가 확보되기 전에는 계산하지 않음.
4. 세 프로젝트는 공통 가상 환자·직원 ID 매핑 가능성을 남기되 MICU의 실제 저장/복원과 간호처방 `ACT/FOLLOW/MAT` 분류를 보호.
5. 기존 UI는 예시이며 향후 변경할 수 있음. 데이터 모델과 출력 화면을 분리하는 원칙 유지.

**참고자료는 사용자가 제공한 교내 학습 PDF로, GitHub 저장소에 원문을 공개·업로드하지 않음.**
