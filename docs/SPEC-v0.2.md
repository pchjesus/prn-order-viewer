# PRN Order Viewer v0.2 — Patient & Review Simulation

**2026-10-10 · 가상 데이터 시연용 · 실제 nU 비연동**

## 목적과 범위
- 임상실습에서 출발한 PRN 탐색 불편을 분석하는 **교육용 EMR 프로토타입**.
- v0.1에서 확정한 초기 전체 약물 탭과 PRN 모든 상태 표시/유효 우선 정렬을 보존.
- 기존 UI의 형태는 고정 요구사항이 아님. 데이터/처방 판단 로직을 UI 배치와 분리하여 이후 전면 재설계 가능하게 유지.

## 시나리오
| Patient | 가상 임상 맥락 | 주요 시연 목표 |
|---|---|---|
| DEMO-P001 | 복부 수술 후 회복 · 통증·오심·배변 변화 | 정규/PRN 혼합, 중지·보류, 두 처방 구분 |
| DEMO-P002 | 검사 후 회복 관찰 | 정규 약물만 존재하는 환자, PRN 0건 |
| DEMO-P003 | 폐쇄성 기도질환 악화 및 복부 불편 | 같은 흡입제의 중지/유효 처방 구분, 진정제 보류, 적응증 누락 |
| DEMO-P004 | 피부·안구 알레르기 증상 및 간헐적 두통 | 외용·점안·경구 제형과 PRN/정규 혼합 |

실제 진료지침이나 기관 프로토콜에서 가져온 환자 시나리오가 아닌 **가상 학습 데이터**.

## 담당자·확인자 모델
- 각 주문의 가상 `prescriber_id/name` 및 `ordered_at`을 별도 필드로 보존.
- 모의 로그인 계정 3명은 D/E/N 각 근무시간 및 ISO 오프셋 시각과 연결.
- 상세정보의 '열람 확인'은 로그인 계정에서 자동으로 간호사 ID/확인 시각을 생성. 임의의 확인자 이름 직접 입력 없음.
- 이전 확인 이력을 order ID별로 표시, 다른 처방 이력을 가져오지 않음.
- 근무시간 외 또는 처방 시각 이전에는 확인 불가. 같은 모의 시각·근무조·처방의 중복 확인을 거절.
- 초기 샘플 확인 3건은 파일에 포함. 새 확인 이력은 **메모리 내에서만 존재**하므로 새로고침 시 사라짐.
- 단순 로그인=열람 확인이 아님. 실제 병원 인증·간호기록·처방 서명·투약 승인은 수행하지 않는다.

## Data contracts
- `data/medication_catalog_candidates.json`: 107개 기존 약물 후보, 변경 없음.
- `data/patients.json`: 4명 가상 환자.
- `data/simulated_orders_SCHEMA_ONLY.json`: 18건 처방, 원래 14건의 ID·환자·정규/PRN·처방 상태 보존, P004용 4건 추가.
- `data/staff_shifts.json`: 근무조·가상 로그인 관계 3건.
- `data/verification_events.json`: 일치하는 간호사·근무시간의 가상 열람 확인 3건.
- `MedicationOrder.is_clinically_complete=false` 및 `dose_review_status='simulation_unverified'`는 모든 처방에 적용.

## 구현 및 검증
- `node --test tests/core.test.cjs`: 14건 통과.
- `python tests/browser_smoke.py`: Chromium 화면(전체/PRN), PC/모바일, 환자 전환, 처방자/확인자, D/E 로그인 전환, 확인 이벤트, 필터·검색, PRN 없는 환자, 콘솔 오류 테스트 통과(가상 JSON 브라우저 주입).
- `python -m http.server 8000`: HTTP 정적 파일 제공 및 JSON 요청 200 로컬 검사 완료. Chromium에서 localhost URL을 여는 것은 현 환경의 관리자 정책으로 불가. Codespaces UI 사용자의 수동 확인 필요.

## 안전·한계
- 약물 용량/경로/빈도는 UI 기능을 위해 구성한 개략적 **가상 예시**, 개별 국내 품목·기저질환/상호작용/기관 지침 검증 없음. 실제 투약·교육용 처방 지시로 사용하지 않는다.
- 처방상태 '유효(active)'는 '현재 투여 가능'을 의미하지 않음.
- UI에서 보여주는 확인 이벤트는 단지 **열람 확인**이며 진짜 법적 감사기록, 본인인증 기록, 처방 승인 아님.
