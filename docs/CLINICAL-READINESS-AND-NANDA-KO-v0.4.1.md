# PRN Order Viewer v0.4.1 — 실제 임상업무 적용 가능성을 고려한 설계 기준

확인일: 2026-10-10 · 현재 앱은 합성 환자/가상 처방 기반 프로토타입이며 **병원 사용이 승인·검증된 EMR이 아니다**.

## 목표와 변경된 우선순위

- 최종 목표: 단순 교육용 화면 복제가 아닌, 의료 현장의 처방 검색·확인·변경·기록 흐름의 **실질적 사용성 및 안전성 개선**.
- 구현 순서: PRN 처방의 탐색·상세정보·의사 변경·간호사 확인·모의 투약·이력 조회를 **안정화**한 다음 검사/진단/간호처방/MICU로 확장.
- 현행 합성 데이터를 실제 처방, 진료기록, 병원 nU 시스템 데이터 또는 진료에 적용할 수 있는 완성 소프트웨어로 설명하지 않는다.
- 실제 병원 워크플로와 기관별 프로토콜은 **미확인**이며, 현직 실무자·담당 부서 검토 및 기관 승인 없이는 일반화하거나 배포하지 않는다.
- UI는 잠정. 변경 가능한 화면 모듈과 독립적인 도메인 규칙/원본 데이터/이벤트를 유지한다.

## NANDA-I 간호진단 한국어 표시 기준 (향후 간호진단 모듈에 적용)

1. **화면 기본 언어는 한국어**. NANDA-I 공식 진단명에 해당하는 경우, 2024–2026 제13판의 **정식 한국어 번역본**에서 동일한 표기를 확인해야 한다.
2. 공식 번역본: 국제간호진단협회 저, 오의금·송라윤·김진숙·박문경·양유리 옮김, 『간호진단: 정의와 분류 2024–2026』, 학지사메디컬, 2025. 한국 국회도서관 서지 및 INKA(NANDA) 공식 한국어판 안내로 존재 확인.
3. **번역 문구를 임의 생성하지 않는다.** 공식 번역본에서 확인하지 못한 용어에는 "공식 한국어 표기 미확인"으로 표시하고, 임의 번역을 공식 간호진단으로 위장하지 않는다.
4. 버전별 진단명·코드·정의·표시언어와 출처를 분리한다. 예시 스키마 후보: `nursing_diagnosis_id`, `taxonomy_edition`, `display_name_ko`, `display_name_en`, `official_translation_verified`, `source_reference`, `license_status`, `institution_mapping_status`.
5. **소프트웨어 저작권/라이선스는 별도 사항.** NANDA/INKA의 분류 콘텐츠는 보호되는 지적재산이며, EMR·앱·데이터베이스 수록·배포/전자적 활용에 이용허락이 필요할 수 있다. 한국어 공식 서적을 확인했다는 사실만으로 전체 진단 목록·정의·코드를 GitHub에 대량 수록할 권한이 발생하지 않는다.
6. 현재 v0.4.1에는 **공식 NANDA 진단명·정의 목록을 추가하지 않음**. 이후 개발 시 사용 권한 확인 또는 대체 합성 테스트 데이터로 최소 시범 기능을 검증한다.
7. NANDA 간호진단 ↔ 병원의 간호진단 등록 ↔ 간호지시/간호수행/기록은 구분. 실제 병원의 간호진단 입력 권한·매핑 체계는 병원마다 다를 수 있으므로 검증 전 확정하지 않는다.

## 실제 의료기관 적용을 위한 필수 관문 (미달성)

한국보건의료정보원(KHIS)의 EMR 인증 기준은 **기능성, 상호운용성, 보안성**으로 구분된다. 이는 현행 앱의 인증/준수를 의미하지 않으며, 향후 기능을 설계할 때 비교 검토할 공식 기준이다.

| 검토 분야 | 이후 필수 과제 | 현재 상태 |
|---|---|---|
| 실제 처방 워크플로 | 기관별 처방 권한·정규/PRN/응급·변경·중지·간호확인 정책 검증 | 합성 시연만 |
| 환자·의료진 식별 | 정확한 환자/입원 ID, 직원 신원 인증, 권한분리 및 세션 정책 | 가상 계정 |
| 의료정보 유효성 | 공식 의약품 정보·진료지침·간호표준·기관 프로토콜 교차검증 | 대부분 미검증 |
| 투약 안전 | 처방 버전·재투여 조건·최대량·투약 기록·독립 확인·오류 방어 | 자동 투약 판단 없음 |
| 법적 기록 | 접근 이력·수정 이력·감사로그·서명/정정/보존·삭제 승인정책 | 탭 메모리 시뮬레이션 |
| 정보보안/개인정보 | 접근통제, 암호화, 비식별 정책, 서버/백업/복원/침해대응, 관계법령 검토 | 실제 정보 사용 금지 |
| 상호운용 | 진료/검사/처방/간호/근무표 간 교환 규격 및 의미·ID 일치 검사 | 읽기 전용 시범 연동만 |
| 검수 | 병원 간호사·의사·간호정보학·보안 담당자와 실제 업무 시나리오 평가 | 사용자 MVP 평가 전 |

**진입 제한:** 위 기준에 대한 적절한 전문 검토와 기관 승인이 이뤄지기 전에는 실제 환자정보를 입력하지 않고, 임상진료/처방/투약 결정에 사용하지 않는다. 보존기간·저장소·사용자 권한 정책을 승인받기 전까지 현재 임시 메모리 방식을 유지한다.

## v0.4.1 안정화에서 적용한 원칙

- 처방 변경 이벤트는 최초 처방 및 직전 변경보다 과거 날짜로 기록하지 않는다. 이벤트 버전을 명시.
- 가상의사가 입력하던 처방은 **같은 환자에서 화면을 닫았다 다시 열어도 보존**하고, 환자 전환 시 초기화한다.
- 새 처방 입력 성공 이후 사용자가 **처방 조회로 이동**할 수 있는 명시적 바로가기 제공.
- 처방 현재 버전의 변경 필드와 최초 처방 원문이 다를 수 있으므로 분리해 안내한다.
- 과거 버전의 열람 확인 기록을 현재 버전 확인이라고 표시하지 않는다.
- MICU 근무표는 읽기 전용, 로그인 인증·처방 확인자와 동치 취급하지 않는다.
- 실제 환자 및 병원 내부 자료를 GitHub/Codespaces/ChatGPT에 업로드하지 않는다.
