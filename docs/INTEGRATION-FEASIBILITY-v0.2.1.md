# MICU 화재대피 ↔ PRN Order Viewer 연동 가능성 검토 및 v0.2.1 적용

**확인 시점:** 2026-10-10 · 교육·시연용 프로토타입 · 실제 병원 통합 아님

## 확인된 현황
- MICU `pchjesus/micu-fire-evacuation` v0.7.4 RC: Excel 기반 근무표, D/E/N, 추가/제외·프로필 수정, IndexedDB 및 SHA-256 전체 백업 JSON(`format: micu-full-backup`, `formatVersion: 1`).
- PRN `pchjesus/prn-order-viewer` v0.2: 4명 가상 환자, 18건 가상 약물 처방, 3건 모의 간호사 세션 및 처방 열람 확인 시뮬레이션.
- 각 앱의 저장소와 브라우저 Origin이 다를 수 있어 IndexedDB 자동 공유 불가. 실제 병원 데이터·환자정보는 두 앱에 업로드하거나 복제하지 않음.
- MICU 앱은 현재 **근무 인력과 화재 역할배치**를 관리하는 프로그램이며 환자정보 관리 시스템이 아니므로, PRN과 환자 데이터셋을 동일하게 맞출 필요가 없음.

## 대안 및 선택
| 방안 | 장점 | 위험 | 판단 |
|---|---|---|---|
| 공동 IndexedDB 직접 접근 | 자동 동기화처럼 보임 | Origin 격리, 기존 데이터 파손, 권한·충돌 | 제외 |
| 두 프로젝트 코드/데이터베이스 통합 | 장기 공통 병동 모델 | 변경 범위·회귀·보안·식별자 통합 부담 | 장기 검토 |
| 서버/API 공통 관리 | 다기기·권한·감사 지원 가능 | 인증·보안·인프라 도입 필요 | 향후 별도 기획 |
| **MICU 백업 → PRN 읽기 전용 선택 가져오기** | MICU 코드/저장 상태 변경 없이 실제 백업 구조 테스트 가능 | 내보내기 파일에 인명·로그 등 포함될 수 있음 | **v0.2.1 시범 적용** |

## 적용 사항
- PRN에 별도 `roster-bridge.js` 및 `roster-bridge-ui.js` 추가. 기존 `app.js`의 조회·필터·투약 판단·확인 이력 로직 **수정하지 않음**.
- 사용자가 MICU **전체 백업(JSON)** 파일을 명시적으로 선택하고 **비식별·승인된 교육용 자료 사용**을 확인해야 조회 가능.
- MICU v0.7.x 백업 형식/버전 및 SHA-256 손상 검증값을 검사(무결성일 뿐 인증·서명 아님).
- 백업 내부 **활성 근무표**만 채택. 사용자가 고른 날짜와 D/E/N 근무조가 실제로 존재할 때만 해당 인원 표시. 근무 코드 `NC`는 원 프로그램의 `ruleSnapshot.dutyCodes`가 지정하면 N으로 정규화.
- 저장된 인원명 변경/근무조별 추가·제외 정보가 존재하면 그 결과만 적용해 **간호사 목록의 읽기 전용 사본** 추출.
- 백업의 로그·수동 역할배치·기타 데이터는 PRN에 표시/전송/저장하지 않으며, 파일은 브라우저 내부에서만 읽고 **새로고침/초기화 시 연결 해제**.
- 가져온 근무자는 **실제 로그인 계정이 아님**. PRN 내 가상 `SIM-RN` 모의 로그인/열람 확인자와 자동 매칭하거나 기존 확인 이력을 변경하지 않음.
- 외부 연동, 파일 서버 업로드, MICU 앱 IndexedDB 변경 및 새로운 공개 URL 생성 없음.

## 절차 (인증된 비식별 시연용 근무표만)
1. MICU 앱(v0.7.4)의 '전체 백업 · 복원' → 전체 백업 JSON 내려받기(다운로드 목록에서 실제 저장 확인).
2. PRN 앱 로컬/Codespaces 화면의 'MICU 근무표 연결'에서 날짜·D/E/N 선택.
3. 비식별·사용 승인 자료만 선택하고 사용 확인 체크 후 '선택 날짜 근무자 조회'.
4. 무결성/활성 근무표/해당 날짜/근무자 데이터 검증. 조회 결과는 이름·그룹·인원수만 현재 탭에서 표시.
5. 결과가 틀리거나 다른 날짜라면 MICU의 활성 근무표·사용 월을 확인. '연결 초기화'로 임시 결과 삭제.

## 안전 및 한계
- **실제 병원 근무표, 직원의 개인정보·환자정보를 승인 없이 ChatGPT/GitHub/Codespaces에 올리거나 반출하지 않는다.** 반드시 허용된 비식별 교육 자료로만 시험한다.
- 파일의 SHA-256은 파일 손상 탐지만 하며 사용자 본인 인증이나 파일 제작자의 신원을 보증하지 않는다.
- '현재 근무자'는 파일 속 날짜·근무코드의 스냅샷일 뿐 실제 근무·근태를 확정하지 않는다.
- 사용자 선택일의 근무표가 없을 때 현재 PRN 로그인 정보를 바꾸거나 가상의 근무자를 채워 넣지 않는다.
- 브라우저 데이터/영구 저장/API/실제 의료정보/환자 동기화는 추가하지 않는다.
- 실제 PRN 처방 열람 확인 기록의 보존·신원 연동은 **독립적인 승인·데이터 정책** 없이 구현하지 않는다.

## 후속 통합 아키텍처 권고
1. 근무표 **최소 정보 교환 규격**(날짜·근무조·가명 직원ID·출처 버전·갱신시각) 마련. 전체 백업 대신 최소 데이터만 별도로 내보내는 방식.
2. 직원 공통 식별자와 실제 로그인/역할 확인을 구분한 계약 수립.
3. 환자정보는 PRN 전용으로 유지. 나중에 MICU 대피 업무가 환자 대피 분류를 관리하게 되더라도 **해당 요구가 실제로 생길 때** 접근권한·비식별 정책과 독립적인 환자 ID 매핑을 협의.
4. 사용자에게 다음 공동 UI/UX 통합 여부, 데이터 저장 범위, 접근권한 정책의 장단점을 제시하고 승인받기 전에는 병합하지 않기.
5. MICU v0.7.4 RC의 현재 정상 동작과 IndexedDB 기존 자료를 우선 보호.

## 검증 범위
- PRN 기존 데이터셋, `app.js`, `data/` 및 MICU 저장소의 코드·저장 데이터 불변.
- 새 브리지 변환 함수의 단위 테스트 파일 `tests/roster-bridge.test.cjs` 추가.
- PRN 브라우저의 실제 MICU 교육용 전체 백업 가져오기는 사용자가 MVP 단계에서 수동 검수 예정.
