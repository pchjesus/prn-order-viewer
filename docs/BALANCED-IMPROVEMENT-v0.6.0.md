# PRN Order Viewer v0.6.0 — 균형 개선형 B안 구현·위험 검토

> 2026-10-13 · **기존 v0.5.2 합성 처방·열람 이력 보존** · 실환자/실직원 자료 사용 금지 · 실제 nU와 무관

## 합의 및 설계 결정
- 사용자가 선택한 B안: 구조화 환자정보, 주치의와 처방 작성자 구분, 업무 유형별 접이식 Kardex, Excel 근무표 직접 읽기 및 저장·사용·삭제.
- **새 저장정책(교육용으로 제한):** 처방·환자정보·가상의사 처방변경·간호사 열람 확인은 기존과 같이 탭 메모리; Excel에서 추출된 근무자/날짜/근무코드만 별도 `prnRosterTeachingDB_v1` IndexedDB에 저장. **원본 Excel 파일·바이너리·병원 실제 직원정보 저장 금지**.
- 근무표의 저장과 사용을 분리; 같은 연월 중복 저장은 확인 후 교체; 삭제 후 활성 근무표는 해제; 최신 revision 검사로 두 탭 교체·삭제 충돌 방어.
- 근무표 정보는 가상 직원의 `D/E/N/NC` 조회에만 사용. **모의 RN 로그인/처방 열람 확인 상태·실제 권한/서명과 자동 연동 없음**.
- 기존 MICU 전체 백업 JSON 조회 기능은 그대로 병존하며 MICU IndexedDB를 열거나 변경하지 않는다.
- 환자·시나리오 자료에 입력되지 않은 알레르기·장치·검사/활력징후는 미확인/미제공으로만 표시한다. 임의의 임상 수치/평가를 추가하지 않는다.

## 단계별 구현
1. **환자/주치의 모델**: `data/patient_profiles.json`(가상 환자 4명)은 원본 `data/patients.json`을 **변경하지 않고** 선택적 상세 프로필을 부여한다. 가상 주치의 ID는 기존 처방자 중 환자별 기본 담당자에서 고른다. `PRNPatientProfiles.validate`는 각 환자의 유일한 프로필과 명시된 미확인 상태를 검증. 작성 의사·변경 의사 필드 자체는 그대로 둔다.
2. **환자 조회 + 가상 처방 입력**: 환자정보에 주치의·알레르기 상태·검사/활력징후 미제공 표기를 추가. 가상의사 선택을 환자 변경 시 주치의 기본값으로 표시하지만 **다른 의사 선택 가능**. 처방 원문의 `prescriber_id/name`와 감사 이력을 변경하지 않는다.
3. **Kardex UI**: 기존 `PRNSheetModel.groupOrders` 순수 모델과 개별 order ID 보존. 화면 표현만 정규·PRN·STAT 세 구획으로 분리, PRN만 기본 펼침; 개별 처방을 클릭하면 원문·작성자·시각·현재 상태·적응증/조건/지시가 나타난다. 원본에 없는 1일 용량·횟수 등을 추정하지 않는다.
4. **Excel 가져오기**: MICU v0.7.5의 공개된 **코드 수준에서 재사용한 순수 config/parser 방식**을 이 저장소에 독립 파일로 복사. 현재 브라우저에서 로컬로 제공되는 SheetJS `xlsx.full.min.js`를 사용해 Excel 시트를 셀 행렬로 읽는다. 시트·연월·이름열/날짜행 자동검출 또는 직접 선택. 20 MB 및 행/열 제한, 유효하지 않은 날짜·알 수 없는 근무코드 거부. 이름/근무 패턴 및 누락 경고를 사용자가 검토한 뒤 저장.
5. **월별 보관함**: IndexedDB stores `rosters` & `meta` (active). 저장·교체·활성 사용·삭제를 명시적으로 구분. 조회 결과는 약물 처방이나 모의 간호사 로그인과 섞이지 않는다.
6. **테스트**: 신규 Node/Chromium 회귀와 기존 `node --test tests/*.test.cjs` 및 `tests/browser_smoke.py`. 이번 보고에서 확인된 실행에 한해 통과 표시.

| 다중 탭 저장 충돌 | 기존 revision 조회와 저장 트랜잭션 중 재확인, 보관함 재조회 필요 |

## 제한과 다음 단계
- Excel은 레거시 MICU 월간 근무표 규칙(날짜행+이름열+근무코드)에 맞춘 것이므로 **모든 병원 근무표 서식을 자동 인식하는 것은 아니다**. 불규칙 파일은 오류 또는 수동 행/열 선택을 요구한다.
- Excel 파일의 개인정보·인사정보를 앱이 자동 비식별화하지 않는다. **실제 병원 파일은 입력하지 않는다**.
- 현재 근무표 저장은 같은 브라우저/주소/프로필에 한정. 기기간 동기화 없음, 파일 백업·내보내기 기능 없음.
- 합성 Kardex의 교육 타당성과 전문 의료진 대상 사용성·임상 안전성은 검증하지 않았다.
- UI는 1차 구조 제안이며 피드백에 따라 소규모 개선할 수 있다. 새로운 저장/동기화/삭제 변경은 사용자 결정 필요.
