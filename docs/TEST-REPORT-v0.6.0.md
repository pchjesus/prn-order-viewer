## 구현 데이터·저장 경계
- 가상 환자 프로필: `data/patient_profiles.json`, 기존 4명 환자 ID와 분리된 환자별 참조. 사정/알레르기/검사/장치는 미확인·미제공을 명시한다.
- 주치의 정보: 환자별 `primary_physician`과 각 처방의 `prescriber_id/name`은 별개. 환자 변경 시 주치의를 신규/변경 시뮬레이터의 기본 선택으로 표시하되 타 가상의사 선택도 허용.
- Kardex: 화면에서만 정규·PRN·STAT 접이식으로 구성. 환자별 원본 처방 ID·작성자·시각·처방 원문은 사라지지 않는다.
- 근무표: 브라우저에서만 Excel을 셀 행렬로 파싱·검증하며, 별도 `prnRosterTeachingDB_v1` IndexedDB에 **월별 해석 결과만** 저장. 사용 지정과 저장은 별도. 삭제 전 확인과 revision 기반 충돌 검사.
- 원본 XLSX 파일 저장·전송, 실제 간호사 로그인 변경, PRN 처방 또는 간호사 열람 이력 영구 저장, MICU 원본 IndexedDB 접근은 없음.

## 확인되지 않았거나 후속 검토할 부분
1. **실제 병원 근무표 사용 금지.** 현재 합성/승인 파일 확인란은 기술적 접근제어/익명화 수단이 아니다.
2. Excel 자동 인식 범위는 복사한 MICU 월간 레거시 파서 프로필에 한정. 다른 병동의 시트 레이아웃, 동명이인, 특수 근무코드 및 빈칸은 사용자 수동 확인/추가 파서 검증 필요.
3. IndexedDB 백업 내보내기/전체 복원, 다기기 동기화, 실제 사용자 다중 로그인/권한은 미구현. 브라우저 사이트 데이터 삭제 후 복구할 수 없다.
4. 같은 달 **교체 확인/타 탭 동시 갱신 차단, 실제 기기별 IndexedDB 데이터 보존**에 대한 수동 검증을 추가할 수 있다. 모델은 해당 충돌 보호를 구현했지만 이번 자동 브라우저 시나리오는 신규 저장/사용/삭제의 1탭 흐름을 직접 검증했다.
5. 화면 가독성은 실제 간호사/학습자 사용성 실험을 수행하지 않았다. CI 통과가 임상적 적절성·환자안전·실사용 편의성의 입증은 아니다.
6. 외부 SheetJS 라이브러리는 MICU 앱의 기존 `vendor/xlsx.full.min.js`를 복사했다. 배포 전 정확한 출처·버전·라이선스 및 취약점 평가가 필요하다.

## 운영 결정
- 이 시스템은 가상 PRN 처방 확인 교육/시연용을 유지한다. 신규 임상 판단 로직·투약 기록 자동 연결은 없다.
- 별도 MICU 앱과 저장소는 그대로 독립 운영한다.
- 추후 UI/저장/환자 관리/기관 실제 연동 확대는 사용자 최종 선택 후 단계별 검증한다.
