## 이 프로젝트에 맞춘 UI/UX 검토 항목

- **명확성:** 전체/PRN/STAT 분류, 처방별 원문·최신 버전·변경 이력, 투여 조건의 **명시/미기재**를 오해 없이 표현한다. 열람 확인을 투여·서명·임상적 승인으로 표현하지 않는다.
- **구조:** 가상 환자별 맥락을 유지하고, Kardex의 접기·펼치기, PRN 핵심 정보, 근무표 조회/가져오기 상태가 서로 혼동되지 않도록 한다. 밀도가 높더라도 중요한 처방 비교·상태 정보는 무리하게 숨기지 않는다.
- **접근성:** 한국어 의학용어와 표·긴 문자열, 320/360/390px·태블릿·데스크톱, 키보드 탐색·포커스 복귀, 200% 텍스트 확대와 리플로우를 **별도로** 검토한다. 색상만으로 위험·상태를 전달하지 않는다.
- **상태/호환성:** PRN 가상 처방·열람 확인의 탭 메모리 상태와 교육용 근무표의 IndexedDB `prnRosterTeachingDB_v1` 저장을 구분한다. 탐색/모달/선택/가져오기/저장·삭제 상태와 환자 분리를 보호한다. 키·스키마 변경 시 구버전 자료 읽기·이전·실패 복구를 설계하고 구버전 자료로 검증한다.
- **사실성:** 실제 환자/직원/처방코드·미검증 임상 수치·병원 직책·선임 등급을 추정하거나 실제 nU 화면으로 오인시키지 않는다.

## 향후 개발 시 적용 절차

1. 최신 `main`, 현재 구현 및 미확정 UX 결정 확인.
2. 사용자 작업 목표, 유지할 상태·원본 데이터·기능을 명시하고 변경 위험도를 L/M/H로 판단. B+ 정책의 DoR·릴리스 절차가 우선한다.
3. 정보 위계 및 상태 전환을 작은 와이어프레임/흐름으로 제시하고 **결정이 필요한 UX 선택은 사용자에게 비교 보고**한다.
4. 승인 범위 안에서 변경; 해당 Node/Chromium 시나리오 및 이전 버전 상태/저장 호환성 검사. 관련 반응형·키보드·접근성 검사 수행.
5. 실제 실행 확인한 결과만 PASS, 미실행·실기기·현직자/임상평가는 NOT RUN으로 구분하여 테스트 기록에 남긴다.

**이번 등록 결과:** 설계 문서와 참조 경로만 변경한다. 앱 코드, 환자/처방/약물 합성 자료, 근무표 DB, 테스트 및 CI 설정은 변경하지 않는다.
