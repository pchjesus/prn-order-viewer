# PRN Order Viewer v0.5.1 — PRN 확인 화면의 정보 우선순위 조정

> 2026-10-10 · 가상 환자·가상 처방 전용 · 임상 검증 미완료

## 배경과 구현 결정
- 승인된 정책: 처방 탐색 → 현재 PRN 지시 확인 → 변경사항 인지에 직접 도움이 되는 기능을 우선한다.
- v0.5 상세정보에서 적응증·조건·용량·경로·빈도/간격·최대 지시가 여러 줄에 흩어져 있어 하나의 읽기 전용 요약 영역으로 모았다.
- 기본 상세정보/원문/열람 확인 이력은 그대로 보존하므로 현재 요약과 원자료를 대조할 수 있다.
- 처방 확인·실제 투약 가능 판단·전자서명/기록 생성을 새로 추가하지 않는다.

## 적용 범위
1. PRN 처방만 상세화면 상단에 `현재 PRN 처방 핵심 확인`을 표시한다. 정규/STAT 화면은 기존 형식 유지.
2. `PRNCore.getPrnConfirmation(order)`: 현재 버전의 명시된 문장형 처방 지시만 필드별로 복사. 누락은 null로 유지하고 구조화 필드에서 자동 역변환하지 않는다.
3. 목록의 약물명 아래 투여 조건(미기재 안내)과 변경된 처방의 버전을 표시한다. 열 추가 없이 기존 검색·상태 필터·정렬 유지.
4. 검색 대상을 PRN 투여 조건 문장으로 확장한다. 환자별/PRN 구분 필터는 먼저 적용한다.
5. 요약에 표시된 처방 상태는 **유효=투약 가능**을 의미하지 않으며 모든 용량·간격은 시연용 미검증 정보다.

## 기존 가상 처방 자료의 범위

- 현재 시드 처방 18건에는 `administration_condition`(PRN 조건)이 별도 구조로 기록되어 있지 않다. **기존 PRN 목록에서 조건은 미기재로 표시**된다.
- 일부 시드의 `frequency_instruction`에 증상 관련 문구가 있더라도, 이를 별도 조건으로 자동 해석하거나 임상 규칙으로 변환하지 않는다.
- 신규 가상 PRN 처방에서는 입력한 `administration_condition`을 그대로 표시·검색할 수 있다.

## 위험 검토 및 보호 사항
- 구버전 구조화 필드: `stale_sections`을 건너뛰는 것이 아니라 **구조화 값 자체를 사용하지 않는다**. 현재 지시 텍스트가 없으면 미기재로 둔다.
- 처방 수정 이후 최신 버전 표시, 처음 입력 원문 별도 표기, 열람 확인의 버전 연결 유지.
- 모든 임상 수치 및 투약 가능 조건은 자동 계산·권고하지 않는다.
- 사용자의 실제 nU 기능을 검증한 것이 아니므로 기존 EMR 대비 효과를 주장하지 않는다.
- 기존 107개 후보, 가상 환자 4명, 기본 처방 18건, 확인 3건, MICU 읽기 전용 연동, 현재 탭 메모리 저장 정책 변경 없음.
- PRN 리스트의 조건 텍스트가 길면 약물명 셀 높이가 증가할 수 있다. 표의 가독성·탐색 속도는 브라우저 및 사용자 검수로 판단한다.

## 검증
- 신규 단위 테스트: `node --test tests/prn-confirmation-v0.5.1.test.cjs`.
- 전체 회귀: `node --test tests/*.test.cjs`.
- UI: 로컬 서버에서 환자 전환, PRN/전체/STAT, 누락 조건, 변경된 처방, 구조화 stale, 모바일 상세 확인.
- 실제 수행: 원격 GitHub의 변경 코드/기존 가상 자료를 이용한 **독립 V8 JS 테스트 하네스**에서 기존·신규 단위/구조 검사 64건 통과. Node 모듈은 모의 구현이며 정식 Node.js test runner를 실행한 결과가 아니다.
- 미수행: 실제 Node.js CLI 전체 테스트, Chromium에서 현 v0.5.1 UI/상호작용 검증 및 MICU 브리지 암호화/백업 테스트 5건. 테스트 파일의 존재를 실행 완료로 취급하지 않는다.

## 향후 보류
- 동일 적응증 PRN 비교 UI, 신규 확인 버튼, 실제 투약 기록/재평가 연동, 자동 투약 적격 판단, 영구 저장은 이번 패치에 포함하지 않았다.
- 사용자 평가에서 조건 요약이 불필요하게 복잡하거나 중복된다고 확인되면 재구성한다.
