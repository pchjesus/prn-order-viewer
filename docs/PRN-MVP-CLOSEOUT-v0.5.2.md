# PRN Order Viewer v0.5.2 — 교육·시연용 MVP 안정화 보고

> 2026-10-10 · 실제 nU/서울성모병원 공식 시스템 및 임상 투약과 무관 · 합성자료 전용

## 변경된 현장 가설
- 출발 가설: 환자별 PRN 약물처방을 별도로 모으면 탐색이 편리해질 수 있다.
- 2026-10-10 비공식 현장 의견: 기존 병원 시스템에 PRN 관련 별도 확인/선택 기능이 있는 것으로 파악된다.
- **미확인:** 실제 nU의 화면·규칙·권한·업무 효율성. 유사 기능이 있다는 의견은 실제 기능의 범위나 사용성을 직접 검증한 사실이 아니다.
- 결정: **PRN 신규 기능 확장은 중단**, 지금 만든 독립형 가상 MVP를 사용 가능하게 안정화한 뒤 보존한다.

## v0.5.2 적용
1. 목록에는 **별도 PRN 투여 조건이 명시된 경우에만** 한 줄로 표시. 기존 가상 시드 18건의 조건이 빠져 있어도 추정·추출·추가하지 않는다.
2. 선택된 PRN 상세에는 적응증/PRN 조건/용량/경로/빈도·간격/최대량 지시를 현재 버전 기준으로 모아 보여준다. 기존 상세 그리드에서 이 여섯 항목의 중복 표시를 생략하되, **정규/STAT 처방의 해당 필드는 유지**한다.
3. 원본 가상 처방·원문·현재 처방의 버전·열람 확인 이력·구조화 자료의 stale 표시·추가 특이사항을 삭제하거나 통합하지 않는다.
4. 검색 힌트에 PRN 조건 포함. 검색/환자분리/PRN 유효 우선 정렬/변경 기능 자체는 변경하지 않는다.
5. 브라우저 검사에서 **실제 HTTP, 전체 JS 로드, 합성 JSON 사용**하도록 전환하고 GitHub Actions의 Node.js·Chromium 테스트 자동화를 추가한다.

## 수용 기준 및 검증 경계
- `node --test tests/*.test.cjs`는 전체 단위 테스트 및 MICU 백업 브리지 테스트를 포함한다.
- `python tests/browser_smoke.py`는 실제 localhost에서 데스크톱/모바일, 4명 환자, 환자별 전체/PRN·필터, 누락 PRN 조건, 모의 열람 확인, 신규 가상 PRN 입력→변경→버전, 새로고침 초기화를 검사한다.
- **실제로 통과한 테스트만 검증 완료로 인정**한다. 성공 여부는 commit에 연결된 GitHub Actions의 최종 실행 상태와 기록으로 판단한다.
- CI는 합성 시나리오 자동 테스트이며 실제 병원 EMR, 사용자 현장 시험, 임상적 안전성·유용성 또는 실제 모바일 기기 검증이 아니다.
- **사용자 기기에서의 최종 육안 확인은 별도 진행할 수 있다.** 가독성은 이 테스트만으로 최종 검증되지 않는다.

## 보호된 데이터와 기능
- 가상 환자 4명, 약물 후보 107종, 시드 처방 18건, 열람 확인 시드 3건 불변.
- 정규/PRN/STAT 분리, 처방 버전, 과거 구조화 stale 표시, 최신/과거 열람 확인 분리 유지.
- MICU 백업 읽기 전용 연동 및 외부 프로젝트 저장소·IndexedDB 불변.
- PRN 신규 처방/이력은 현재 브라우저 탭의 메모리에서만 보존. 서버/로컬 영속저장·백업·삭제 정책 추가 없음.

## 재사용할 핵심 자산
- `order-history-model.js`: 처방 변경 이벤트/현재 상태/변경 전후 스냅샷의 모델과 회귀 테스트.
- `order-structure.js`: 실제 임상 유효성과 무관하게 **명시된 입력을 구조화**하고 충돌/누락을 통제하는 방식.
- `app.js`: 원문/현재 지시/간호사 열람 확인을 별도로 다루는 조회 상태 모델과 목록–상세 UX.
- `tests/`와 GitHub Actions 워크플로: 합성자료 기반 안전한 개발/회귀 검증 방법.

이 요소를 간호처방 프로젝트에 그대로 병합하지 않는다. 기존 간호처방 프로젝트의 기능형 MVP와 **겹치는 기능을 먼저 확인**하고 필요한 개념만 독립적으로 차용한다.
