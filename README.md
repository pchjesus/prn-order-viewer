# PRN Order Viewer v0.5 — Synthetic EMR PRN Medication Viewer

> **EDUCATIONAL PROTOTYPE / SYNTHETIC DATA ONLY**
>
> 실제 가톨릭중앙의료원 nU 또는 서울성모병원 공식 시스템과 관계없는 독립형 교육·시연용 웹앱.
> **실제 환자정보, 실제 처방코드, 실제 병원 프로토콜을 포함하지 않음.**
> **실제 투약·임상적 판단에 사용 금지.**

## v0.5 — 명시적 구조화 처방

- 기존 문장형 처방 입력을 계속 사용할 수 있고, 가상의사 입력 화면의 접이식 영역에 구조화 값을 선택적으로 입력할 수 있습니다.
- `instruction_structure`는 명시적 가상 제품·제형·함량, 용량 값·단위, 경로 코드, 빈도·간격·시각, 최대 지시와 PRN 조건을 분리합니다.
- 같은 항목을 문장형과 구조화형에 다르게 작성하면 등록을 거부하며, 값·단위 같은 필수 쌍의 누락도 거부합니다.
- 변경된 문장형 지시에 연결된 과거 구조화 절은 `stale_sections`로 표시하되 삭제하지 않습니다.
- 기존 18건을 자동 해석하지 않으며 107개 약물 후보에 검증되지 않은 제형·함량·용량을 일괄 추가하지 않습니다.
- 임상 검증, 실제 투여 가능 판단, 영구 저장, JSON 백업·복원은 이번 버전 범위가 아닙니다.
- 자세한 구조와 검증 한계: `docs/ORDER-STRUCTURE-v0.5.md`.

## 문제 및 목표

가상 전체 약물 처방 목록에서 필요시(PRN) 약물 처방을 빠르게 식별하고 원문·누락값을 함께 확인하는 **가상 시나리오, 모듈형 업무화면, 의사 처방 변경 이력을 가진 v0.4 교육용 웹앱**이다. 실제 nU 화면을 복제하거나 병원 시스템을 연동하지 않는다.

## 조사 결과와 한계

- 107개 **후보 성분/제제**를 18개 증상·목적 중심 카테고리로 정리함.
- 'PRN 후보'는 실제 임상 빈도·국내 품목 허가·nU 처방 존재·병원별 관행을 입증하는 말이 아니다.
- **모든 후보의 개별 허가/제품/투여정보는 추가 검증 전(`individual_review_pending`)**.
- 실제 약물 용량·간격·최대량, 처방 허용 여부 및 투여 판단은 기입하지 않음.
- `simulated_orders_SCHEMA_ONLY.json`의 처방은 **18건의 시연용 비임상 처방**이며, 일부 가상 용량·경로·간격이 입력되어 있지만 실제 환자별 처방 적합성은 검증되지 않았다. **투약 근거로 사용 금지**.

## 실행 방법 (Private 저장소 로컬/Codespaces 터미널)

먼저 저장소 루트 디렉터리에서 최신 파일을 가져온 뒤 로컬 HTTP 서버를 실행한다.

```bash
git pull origin main
python -m http.server 8000
```

`python` 대신 `python3` 또는 Windows의 `py` 사용 가능. 로컬 브라우저에서 `http://localhost:8000` 접속. GitHub Codespaces 환경에서는 **Ports → 8000 → Open in Browser** 사용(공개 포트로 변경하지 말 것). GitHub Pages나 별도 공개 웹주소는 사용하지 않는다.

직접 `index.html` 파일을 더블클릭하면 브라우저의 `file://` 보안 정책 때문에 JSON 데이터 읽기가 차단될 수 있다. 서버로 열어야 한다.

## 테스트

```bash
node --test tests/*.test.cjs
```

v0.2 시점의 Node.js 테스트 **14건 통과**. v0.3 추가 후 GitHub 원격 소스를 이용한 별도 JS 실행 환경에서 기존 14건 + 신규 8건 = **22/22 통과**(현재 수정본의 실제 Node.js 명령 및 브라우저 UI 검증은 별도 미완료). Chromium에서 HTML·CSS·JavaScript를 실행하고 로컬 가상 JSON을 주입한 **데스크톱/모바일 상호작용 확인**도 수행했다. 검증 환경의 네트워크 제한으로 실제 localhost HTTP 접속은 테스트하지 못했으므로 사용자 터미널에서 수동 실행 확인이 필요하다.

## v0.2 사용 방법

1. 환자 선택에서 가상 환자 4명 가운데 한 명을 선택하여 과거력·현재 병력을 확인한다.
2. 전체 약물/PRN 약물 탭에서 해당 환자에 연결된 가상 처방을 조회한다.
3. 모의 로그인 근무조(D/E/N)를 변경하면 화면의 로그인 간호사·시각이 달라진다.
4. 처방 상세에서 가상 처방자 및 이전 **열람 확인** 이력을 확인하고, 로그인된 모의 간호사로만 새 열람 확인을 기록한다.
5. 새 기록은 **현재 브라우저 탭 메모리에만 남고 새로고침 시 사라진다**. 실제 로그인·서명·투약 승인·법적 기록이 아니다.

## 장기 개발 목표: 실제 병원 업무의 안전성과 편의성을 개선하는 EMR

이 프로젝트의 장기 목적은 가상 화면 자체가 아니라 **병원 처방의 탐색·확인·변경·기록 과정에서 발생하는 실제 불편을 개선하는 것**이다. 처음에는 PRN 기능을 안정화하고, 이후 검사·간호진단·간호처방·근무표를 모듈 방식으로 연결한다. UI는 잠정 구조로 유지한다.

**현재는 여전히 합성 환자/가상 처방을 사용하는 연구·기술검증 단계이며, 임상 사용 가능한 EMR이나 인증된 의료기기가 아니다.** 실환자·실제 병원 코드/로그인정보를 입력·수집·공개·전송하지 않는다. 실제 병원 적용 전에는 병원 정책·임상 검증·인증/보안/법률 요건과 사용성 평가가 필요하다.

향후 NANDA-I 간호진단은 **공식 한국어 번역본 『간호진단: 정의와 분류 2024–2026』(2025, 학지사메디컬)**의 정확한 한국어 표기를 기준으로 삼는다. 임의 번역을 공식 명칭이라고 부르지 않으며, 전자적 수록·활용 전 권리자 이용허락/라이선스를 확인한다. **현재 앱에는 NANDA 공식 진단 목록을 수록하지 않는다.**

세부 기준: `docs/CLINICAL-READINESS-AND-NANDA-KO-v0.4.1.md`.

## v0.4.1: 의사 처방·열람 확인 흐름 안정화

- **처방 변경 이력의 시간 정합성:** 이전 변경 시각보다 이른 이벤트를 거절. 이벤트마다 처방 버전 명시.
- **의사 처방 초안 보호:** 같은 환자의 입력 화면을 닫고 다시 열어도 선택 약물/의사/시간을 보존. 환자를 바꾸면 미등록 입력을 초기화.
- **업무 이동 편의:** 등록 완료 후 '등록한 처방 조회하기' 버튼으로 약물 목록으로 직접 이동.
- **처방 원문 구분:** 변경 후 화면의 최신 처방 정보와 최초 입력 원문이 다를 수 있음을 명확히 표시. 변경된 현재 버전의 간호사 열람 확인과 이전 버전 확인 구분.
- **MICU 연결 오류 안내:** 사용(활성) 근무표 누락 메시지를 명확히 표시.
- 저장·복원 정책은 아직 확정되지 않았으므로 새로운 처방과 이력은 **현재 탭 메모리 한정**으로 유지한다.

검증: GitHub 현재 소스 기반 독립 JavaScript 실행 환경에서 기존 로직·구조 42개 + 신규 안정화 8개 = **50/50 통과**. 기존 MICU 백업 연동 테스트 **5/5 별도 통과**(MICU 구현의 SHA-256 검증 방식과 호환성 점검). 합계 **55건 모두 통과**. 실제 Node.js/Codespaces 명령 및 수정 후 브라우저 조작 검증은 아직 별개로, 미실시 검증을 성공으로 간주하지 않는다.

## v0.4: 사이드바 업무 화면 전환 + 처방 변경 이력

기존처럼 모든 자료를 한 화면에 쌓지 않고, **왼쪽 사이드바**에서 6개 업무영역을 선택해 해당 화면만 표시한다.

- **약물 처방 조회** (기본): 전체/PRN 탭·처방 상세·모의 간호사 로그인/열람 확인.
- **환자 정보**: 선택 환자의 병력·현재 상태.
- **인계·Kardex**: 교내 실습자료 기반의 가상 워크리스트·인계·처방지 미리보기.
- **의사 처방 입력**: 정규/PRN/STAT 약물 시뮬레이션.
- **처방 변경 이력**: 가상의사가 처방을 변경, 보류, 재개, 중지(D/C), 취소하는 모의 이벤트.
- **MICU 근무표**: 기존 교육용 백업 파일 읽기 전용 조회.

상단 가상 환자 선택은 모든 업무화면에서 공통으로 유지. 메뉴 전환은 자료를 다시 불러오거나 초기화하지 않는다. 모바일에서는 사이드바 대신 상단 가로 메뉴로 표시한다. **UI는 잠정 설계**이며 모듈별 교체가 가능하도록 분리했다.

새 처방/변경 이력은 **현재 브라우저 탭 메모리에만 보존**된다. 기존 처방 파일을 수정하지 않고 변경 전/후 스냅샷을 별도 이벤트로 기록한다. 처방 상태와 처방 버전별 간호사 열람 확인을 혼동하지 않는다.

새 파일: `workspace-nav.js`, `order-history-model.js`, `history-ui.js`, `tests/workspace-nav.test.cjs`, `tests/order-history-model.test.cjs`.

**검증 범위:** 기존 29건 + 이력 9건 + 사이드바 4건 = **42/42 로직·구조 테스트 통과**(GitHub 현재 소스와 가상 데이터를 활용한 독립 JS 실행 환경). 실제 Codespaces Node 테스트·브라우저 렌더링·최종 시각검수는 미실시. MICU 브리지 별도 테스트는 이번 변경에서 재실행하지 않음.

설계 및 위험 검토: `docs/WORKSPACE-AND-ORDER-HISTORY-v0.4.md`.

기존 **전체 약물/PRN** 조회 화면을 보존하면서, 접을 수 있는 **의사 약물 처방 입력 · 시뮬레이션** 화면을 추가했습니다.

1. 가상 환자 4명 중 조회 중인 환자를 대상으로, 기존 가상 처방자·약물 후보 107개를 선택합니다.
2. 정규·PRN·응급(STAT)을 선택하고 **용량·투여경로·빈도·시간**을 직접 입력합니다. PRN은 적응증과 투여 조건도 필수입니다.
3. '가상 약물처방 등록' 후 현재 환자의 전체 약물 또는 PRN 탭에 즉시 추가되고 상세정보/검색에 반영됩니다.
4. **응급(STAT)은 긴급도**, PRN은 필요시 투여 조건입니다. v0.3에서 응급 선택은 정규 목록의 STAT 우선순위로 표시하며 PRN으로 자동 분류하지 않습니다.
5. 생성한 새 처방은 현재 탭 메모리에만 있으며 **새로고침 시 없어집니다**. 실제 의사 처방, 서명, 인증, 투약 승인 또는 임상적으로 검증된 용량이 아닙니다.
6. 드레싱/처치, 검사(객담 배양 등), 검체 종류, SST/EDTA 채혈관은 앞으로 별도 데이터 영역으로 확장 예정이며 **현재 입력 기능은 약물만** 지원합니다.

신규 파일: `order-composer.js`(독립 가상 처방 생성/검증), `doctor-ui.js`(접이식 의사 입력 화면), `tests/order-composer.test.cjs`(새 입력 경로·처방 구분 테스트).

참고 문서: `docs/THREE-PROJECT-CONVERGENCE-v0.3.md` — MICU 근무표, PRN 의사처방, 간호처방 개선 앱의 향후 통합과 데이터 경계.

**검증:** 현재 GitHub 원격 소스와 원본 가상 데이터를 불러와 별도 JS 실행 환경에서 새로운 처방 생성·PRN 조회·응급 구분·기존 데이터 비변경 등 **16개 점검 통과**. 추가 Node.js 테스트 파일을 등록했으나 신규 전체 `node --test tests/*.test.cjs`와 수정 후 실제 브라우저 UI 검증은 사용자 MVP 검수 전까지 미확인 상태입니다.

## v0.2.1: MICU 근무표 읽기 전용 시범 연동

MICU 화재대피 앱 v0.7.4 RC의 전체 백업 JSON을 **사용자가 선택한 경우에만** 읽어 활성 근무표의 날짜·D/E/N 근무 간호사 명단을 PRN 화면에서 미리 볼 수 있습니다.

1. MICU 앱의 '전체 백업 · 복원' 메뉴에서 **비식별 교육용 자료만** 백업합니다. 병원 직원의 실제 개인정보나 내부 근무자료는 승인 없이 반출하거나 업로드하지 마세요.
2. PRN 화면의 'MICU 근무표 연결' 영역에서 날짜·듀티 선택 후 JSON 파일을 선택하고 허용자료 확인에 체크합니다.
3. 파일 형식과 MICU SHA-256 무결성 검사 후 **조회 전용 목록**만 표시합니다. 활성 근무표가 없거나 해당 날짜가 없으면 오류 안내가 나옵니다.
4. 원본 백업 파일은 브라우저 내부에서만 처리하며 다른 서버에 전송하거나 브라우저 저장소에 기록하지 않습니다. 새로고침 또는 연결 초기화 후에는 목록이 남지 않습니다.
5. **근무자 목록은 실제 로그인/간호사 본인 인증을 뜻하지 않습니다.** 기존 PRN 가상 로그인 및 처방 열람 확인 이력과 자동 연결하지 않습니다.

이 연동은 두 앱의 **데이터베이스를 합치지 않으며**, MICU 저장소 코드·근무표/IndexedDB·PRN 환자/처방 데이터를 변경하지 않습니다. 구조 및 위험 검토: `docs/INTEGRATION-FEASIBILITY-v0.2.1.md`.

새 파일:
- `roster-bridge.js`: MICU 전체 백업 검증 및 근무표 읽기 전용 변환
- `roster-bridge-ui.js`: PRN 화면 내 독립형 근무표 가져오기 영역
- `tests/roster-bridge.test.cjs`: 가상 백업의 근무조·무결성·비간섭 테스트

**테스트 상태:** 원본 MICU SHA-256 구현과 신규 브리지의 파일 검증/근무조 해석에 대한 독립 실행 검사를 수행했습니다. 신규 Node.js 테스트 파일은 등록했으며 전체 `node --test tests/*.test.cjs` 및 사용자 브라우저 연동 검증은 후속 실행이 필요합니다. 기존 PRN v0.2 테스트 14개는 당시 통과했습니다.
